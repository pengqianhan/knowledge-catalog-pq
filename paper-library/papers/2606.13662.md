# Summary

This paper introduces EurekAgent, an environment-engineered agent system for metric-driven autonomous scientific discovery. Its central argument is that as model capabilities improve, the bottleneck for autonomous discovery shifts from *prescribing agent workflows* to *designing agent environments*: the resources, constraints, and interfaces that shape agent behavior.

The authors frame this as **environment engineering** — building environments that amplify productive behaviors (open-ended exploration, systematic artifact management, inter-agent collaboration) while suppressing harmful ones (reward hacking, high-friction human oversight).

# Key Ideas

* Given an optimizable metric and an execution environment, LLM agents can propose, validate, and iterate solutions, sometimes beating human-designed approaches.
* The paper reframes the open problem from "what workflow should the agent follow" to "what environment should the agent act in."
* Environment design is treated as a lever for both encouraging exploration and curbing failure modes such as reward hacking.

# Method

EurekAgent engineers the environment along four dimensions:

* **Permissions engineering** — bounded agent execution and isolated evaluation.
* **Artifact engineering** — filesystem and Git-based collaboration for managing artifacts.
* **Budget engineering** — budget-aware exploration under cost constraints.
* **Human-in-the-loop engineering** — easy human supervision and intervention.

# Experiments

* Reports new state-of-the-art results on multiple mathematics, kernel engineering, and machine learning tasks.
* Highlights a new state-of-the-art 26-circle packing result discovered for less than $11 in total API cost.
* Code and results are open-sourced (no repository URL captured from the abstract page).

# Limitations

Not yet assessed from the full text; the points below are reading flags rather than established critiques.

* The four engineering dimensions are described at a system level in the abstract; the per-dimension ablations and how much each contributes are not yet verified here.
* "State-of-the-art on multiple tasks" needs checking against which baselines and task selections.

# Notes

Reading questions:

* How does permissions/isolation engineering concretely prevent reward hacking versus simply detecting it after the fact?
* How does the Git-based artifact substrate compare to shared-context approaches like DeLM for inter-agent collaboration?
* The $11 / 26-circle-packing result is a striking cost claim — what is the full cost distribution across tasks, not just the headline?
* Which environment-engineering ideas (permissions, artifacts, budget, human-in-the-loop) transfer to OKF library curation as an "agent environment"?
